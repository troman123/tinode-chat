# Modifications

This is a modified copy of [tinode/chat](https://github.com/tinode/chat), distributed
under the same GPL-3.0 license as the original. This file records the modifications, as
required by section 5(a) of the license. The full history of every change, with dates and
diffs, is in the git log of this repository.

All modifications are general-purpose: they add configuration options, and every value they
act on comes from the runtime configuration. None of them is specific to any particular
deployment.

| Date | Change |
| --- | --- |
| 2026-08-05 | `auth/rest`: optional `service_jwt` config section. When present, the REST authenticator signs each outgoing request with a short-lived ES256 JWT bound to the request's method, path and body hash. Absent by default; without it the authenticator behaves exactly as upstream. |
| 2026-08-05 | Server: optional `grpc_tls` config section, letting the gRPC listener use a TLS configuration separate from the HTTP one. Both sections accept `client_ca_file` and `require_client_cert` for client certificate authentication. Absent by default; without it the gRPC listener shares the HTTP TLS configuration as upstream. |
| 2026-08-06 | Server: redact authentication secrets from the gRPC packet log. `hdl_grpc.go` logs every inbound packet verbatim at info level, which puts the `secret` of a `{login}` or `{acc}` packet in plain text into the server log. Sensitive fields are now replaced by a fixed placeholder before the packet is rendered; field names, packet ids, the authentication scheme and everything else are kept. Redaction is by protobuf field name, so a field added later is covered as soon as it appears. Applies to all schemes and all log levels; the message being logged is not modified. |
| 2026-08-07 | Server: redact authentication secrets from the websocket and long polling packet log, and from the file upload authentication log. `session.go` logs every inbound packet verbatim at info level before parsing it, which puts the `secret` of a `{login}` or `{acc}` packet in plain text into the server log — the same defect as the gRPC one above, on the transport the previous change did not cover. The packet is now parsed, its sensitive fields replaced by a placeholder, and re-serialised before it is logged; a packet that does not parse is logged as its size only, since nothing can be shown to be safe in a packet whose structure is unknown. `hdl_files.go` printed the upload authentication secret whenever it failed to base64-decode; it now prints the scheme and the session id. The field names are shared with the protobuf redaction, so neither wire format can be extended without the other. |
| 2026-08-09 | Server: restrict changing another member's granted access in a P2P topic to a root session. In a P2P topic `A` cannot be removed from either member — both `hub.go` and `thisUserSub` force `| ModeApprove` — so every member is an approver, `IsAdmin()` is always true, and any member could set the peer's `ModeGiven` at will, including undoing a grant issued through the administrative path. `anotherUserSub` now refuses such a change unless the session is authenticated at root level; the check reads the session's auth level rather than the packet's, because on-behalf-of lowers the packet level to auth. Creating a subscription, re-sending an invite without a mode change, and changing one's own `ModeWant` are unaffected, as are group topics. Note this narrows upstream behaviour: a client that implements "block contact" by lowering the peer's grant will need root or a different mechanism. |
| 2026-08-05 | `keygen`: stop echoing a salt supplied via `-salt`. A caller passing the salt already holds it; printing it again only leaks a long-lived secret into terminal history and logs. A salt generated by keygen itself is still printed. |
